# Красивый дизайн — описание фичи

## О чём фича

Сейчас приложение работает, но выглядит как «учебный shadcn-проект»:

- одинаковая «серая в синюю» палитра везде, ничего не выделяется визуально;
- баланс показан тремя сухими карточками без иерархии — глаз не цепляется
  за главную цифру;
- список транзакций — обычная HTML-таблица, не дышит, ничего не подсказывает
  о категориях и периодах;
- формы и диалоги — дефолтный shadcn без полировки (плотность, отступы,
  состояния focus/hover/disabled);
- нет тёмной темы, хотя CSS-переменные `:root` и `.dark` уже заведены
  в `globals.css`;
- авторизационные страницы выглядят как заглушки;
- админка — голая таблица.

Цель — **сохранить весь функционал и архитектуру (Server Components,
Server Actions, Supabase, RLS)**, но переработать визуал: типографику,
палитру, компоненты, иконки, состояния, тёмную тему и адаптив.
Никакой смены стека.

## Принципы дизайна

1. **Деньги — главное.** В дашборде цифра баланса — самый крупный
   элемент на экране. Всё остальное (фильтры, кнопки, мета-информация)
   тише по контрасту.
2. **Чёткий смысловой цвет.** Зелёный = доходы, красный = расходы,
   navy = бренд/нейтрально-важное, серый = вспомогательное. Никаких
   декоративных цветов «для красоты».
3. **Тихая палитра + один акцент.** Основа — нейтральные оттенки
   (бумага / графит). Акцент бренда — глубокий navy `--primary`.
   Семантика (income/expense) — отдельные шкалы.
4. **Геометрия и ритм.** Единая шкала отступов 4/8/12/16/24/32,
   радиусы из `--radius` (sm/md/lg/xl/2xl), типографика по модульной
   шкале (12/14/16/20/24/32/40/56).
5. **Состояния важнее украшений.** Каждый интерактивный элемент имеет
   видимые состояния: default / hover / active / focus-visible / disabled
   / loading. Без них приложение «мёртвое».
6. **Тёмная тема — не опция, а равноправный режим.** Цвета и контрасты
   спроектированы сразу под обе темы (AA по WCAG, иконки и графики
   читаемые на обоих фонах).
7. **Доступность по умолчанию.** Семантика HTML, фокус-кольца,
   контраст 4.5:1 для текста и 3:1 для крупного, поддержка
   клавиатуры и screen readers, `prefers-reduced-motion`.
8. **Минимум новых зависимостей.** Иконки — `lucide-react` (уже частый
   спутник shadcn). Графики — `recharts` (опционально, см. ниже).
   Анимации — `tw-animate-css` (уже подключён) + Framer Motion
   допустим **только** в одном-двух местах, где он реально окупается.

## Технический стек (что используем для дизайна)

- **Tailwind CSS 4** + CSS-переменные shadcn (всё уже подключено
  в `globals.css`)
- **shadcn/ui** — продолжаем достраивать компоненты (`Tooltip`,
  `Skeleton`, `Sonner` для тостов, `Tabs`, `Separator`, `Avatar`,
  `Sheet` для мобильного меню)
- **`lucide-react`** — единый набор иконок, заменяет emoji
  («₽», «📋», «✕», «⋯»)
- **`next/font`** — пара шрифтов: `Inter` (UI) и `JetBrains Mono`
  (цифры/таблицы). Уже подключён `Geist` — оставляем как UI-шрифт,
  моно-шрифт добавляем
- **`next-themes`** — переключатель light/dark/system, сохранение в
  cookie/localStorage, без `flash of wrong theme`
- **`framer-motion`** (опционально) — только для анимации цифры
  баланса и появления списка транзакций
- **`recharts`** (опционально, бонус) — мини-спарклайн «расходы за
  последние 7 дней» под карточкой баланса

### Типографика

- **UI-шрифт**: `Geist` (уже подключён в `app/layout.tsx`)
- **Моно-шрифт для цифр**: `JetBrains Mono` через `next/font`,
  переменная `--font-mono`, класс `font-mono` применяется ко всем
  денежным значениям и табличным колонкам сумм/дат
- Шкала размеров (Tailwind утилиты):
  - `text-xs` (12) — мета, подписи, метки фильтров
  - `text-sm` (14) — основной текст в формах и таблицах
  - `text-base` (16) — кнопки, label
  - `text-lg` (18) — заголовки секций
  - `text-xl` (20) — заголовки карточек статистики
  - `text-3xl` (30) — крупные цифры в `StatCard`
  - `text-5xl` (48) — **главная цифра баланса** на дашборде
- Высота строки `leading-tight` для заголовков, `leading-relaxed`
  для длинных описаний
- `tabular-nums` (через `font-variant-numeric`) на всех денежных
  значениях, иначе цифры «прыгают» при изменении

### Отступы, радиусы, тени

- Сетка 4 px: используем шаги Tailwind `1/2/3/4/6/8/10/12/16/20`
- Радиусы: уже есть `--radius` = `0.5rem`. Применяем строго:
  - кнопки и инпуты — `rounded-md`
  - карточки, плашки — `rounded-lg`
  - модалки, sheet — `rounded-xl`
  - badge — `rounded-full` (pill)
- Тени:
  - `shadow-xs` — карточки в покое
  - `shadow-md` — header, sticky-зоны
  - `shadow-lg` — модалки, popover, dropdown
  - На dark — тени не работают, используем `border-border` сильнее

### Иконография

- Только `lucide-react`, размер по умолчанию **16 px** в таблицах
  и кнопках, **20 px** в заголовках и пустых состояниях,
  **24 px** только в hero-зонах
- Маппинг (минимум, расширяем по ходу):
  - `Wallet` — логотип бренда (заменяет «₽» в шапке)
  - `Plus` — добавить транзакцию
  - `LogOut` — выйти
  - `Shield` / `ShieldCheck` — админка
  - `TrendingUp` — доходы
  - `TrendingDown` — расходы
  - `Scale` — баланс
  - `Pencil` — редактировать
  - `Trash2` — удалить
  - `Search` — фильтр/поиск
  - `Sun` / `Moon` / `Laptop` — переключатель темы
  - `Github`, `Mail` — соц-логин (вместо «Войти через GitHub» — иконка + текст)

### Анимация

- Длительности: `duration-150` (hover/focus), `duration-200`
  (открытие popover/dropdown), `duration-300` (открытие dialog/sheet)
- Кривые: `ease-out` для появления, `ease-in` для исчезновения
- Каждый анимированный блок уважает `@media (prefers-reduced-motion: reduce)` —
  в `globals.css` добавляем правило `* { transition: none !important;
  animation: none !important; }` под media-query

## Главные блоки дизайна

### 1. Тема: light / dark / system

- Подключаем `next-themes` в `app/layout.tsx` через
  `<ThemeProvider attribute="class" defaultTheme="system">`
- В `head` через `<script>`-инлайн (стандартный паттерн `next-themes`)
  избегаем мерцания при первой отрисовке
- Кнопка переключателя темы — компонент `ThemeToggle`:
  кнопка-иконка `Sun` / `Moon` в шапке (и публичной, и админской)
- Меню `DropdownMenu`: «Светлая / Тёмная / Системная»
- Все цвета приходят из CSS-переменных — никаких `dark:bg-*` хардкодов
  в компонентах. Если такое есть (например, в текущих
  `balance-summary.tsx`, `transaction-list.tsx`) — рефакторим
  под токены `--success`, `--danger`

### 2. Глобальная навигация (`AppHeader`)

Текущая шапка в `app/page.tsx` инлайнится в страницу. Выносим в общий
компонент `<AppHeader />` в `components/layout/app-header.tsx`:

- Sticky, `top-0`, `backdrop-blur` + полупрозрачный фон
  (`bg-background/80`)
- Слева — `<Logo />`: иконка `Wallet` в скруглённом квадрате
  `--primary`, рядом «Money Tracker» (text-base, font-semibold)
  и под ним мелкая мета — email пользователя (`text-xs
  text-muted-foreground`, не на цвете primary как сейчас)
- В центре (на десктопе) — `<MainNav />`: ссылки «Транзакции» /
  «Аналитика» (зарезервировано) / «Админка» (только для admin),
  активная ссылка подсвечена линией снизу или фоном `bg-muted`
- Справа — кластер действий:
  - `<ThemeToggle />`
  - `<UserMenu />` — `Avatar` (инициалы из email) + `DropdownMenu`
    с пунктами «Профиль (заглушка)», «Выход»
  - На главной — основной CTA `<AddTransactionButton />` (стиль `default`)
- На мобильных (`<md`): главная навигация прячется в `Sheet`-меню
  по иконке `Menu`. CTA «+ Добавить» становится плавающей FAB
  (`fixed bottom-6 right-6`)

### 3. Дашборд транзакций (`/`)

Самая частая страница — делаем её самой красивой.

#### 3.1. Hero-блок «Баланс»

Заменяем три одинаковые карточки одним hero-блоком:

```
┌──────────────────────────────────────────────────────────┐
│   Баланс за май 2026                                     │
│   +47 350 ₽                  ← крупная цифра, font-mono  │
│   ───────────                                            │
│   ↑ Доходы 65 000 ₽    ↓ Расходы 17 650 ₽    ●●●●●○○    │
└──────────────────────────────────────────────────────────┘
```

- Карточка `Card` во всю ширину, `rounded-xl`, `shadow-xs`
- Сверху — название текущего месяца (`text-sm text-muted-foreground`)
  и компактный селектор месяца (стрелки `<` `>` + название) — позже
- Главная цифра — `text-5xl font-mono font-semibold tabular-nums`

### 4. Форма транзакции (диалог)

Сейчас — функциональная, но плотно сжатая форма. Переделываем:

- Радио «Доход / Расход» — заменяем на segmented control: две
  большие плитки бок о бок, выбранная — заполнена цветом
  (`bg-success-soft text-success` или `bg-danger-soft text-danger`)
  и иконкой `TrendingUp` / `TrendingDown` сверху
- Сумма — `Input` крупный (`h-12 text-2xl font-mono`), с префиксом
  «₽» слева внутри инпута (через wrapper-div)
- Категория — `Select` с иконкой категории внутри `SelectItem`
- Описание — `Textarea` (а не `Input`), 2 строки, счётчик «n/280»
  справа снизу
- Дата — `Input type="date"` оставляем, но рядом — две кнопки
  быстрого выбора: «Сегодня», «Вчера»
- Кнопки внизу: `Отмена` (variant `ghost`), `Сохранить`
  (variant `default`), на полную ширину, на мобильных
  стеком сверху вниз
- Ошибки полей — красная подпись + красная рамка инпута через
  `aria-invalid`-вариант, ошибка верхнего уровня — `Alert`
  c иконкой `AlertCircle`

### 5. Страницы аутентификации (`/login`, `/register`)

Текущая раскладка — карточка по центру на сером фоне. Делаем
split-layout как в современных SaaS:

- На десктопе (`md+`) — две колонки 1:1:
  - **Левая** — форма входа/регистрации в `Card` (макс. ширина 400px),
    логотип сверху, форма по центру вертикально
  - **Правая** — «гость-зона»:
    - Лёгкий градиент `from-primary to-primary/80` или
      «бумага в клетку» через CSS-grid-фон

## Доступность (a11y)

- Контраст:
  - текст на фоне ≥ 4.5:1 (проверяем все пары `--foreground` /
    `--background`, `--muted-foreground` / `--muted`,
    `--primary-foreground` / `--primary`)
  - иконки и крупный текст ≥ 3:1
- Семантика:
  - таблицы — `<table>`, `<thead>`, `<tbody>`, `<th scope="col">`
  - формы — `<label htmlFor>` для каждого инпута, `<fieldset>`/
    `<legend>` для радио-группы (уже есть в `transaction-form.tsx`)
  - модалки — корректный `aria-labelledby` (shadcn делает сам,
    проверить, что заголовок присутствует)
- Клавиатура:
  - все диалоги — `Esc` закрывает, фокус возвращается на триггер
  - таблицы — кликабельная строка дублируется кнопкой «Изменить»
    (нельзя полагаться только на onClick по `<tr>`)
  - FAB и плавающие элементы — в табордере
- Screen-readers:
  - иконочные кнопки — `aria-label` («Удалить транзакцию»,
    «Переключить тему», «Открыть меню пользователя»)
  - статус «Загрузка» — `aria-live="polite"` на области тоста
- `prefers-reduced-motion` — отключает все `transition` и
  `animate-*` в `globals.css`

## Дополнительные правила

- **Только токены.** В компонентах запрещены прямые цвета
  Tailwind вида `text-emerald-700`, `bg-rose-50`. Только классы
  через CSS-переменные: `text-success`, `bg-success-soft`,
  `text-danger`, `bg-danger-soft`, `text-muted-foreground` и т.п.
  Если такого класса нет — заводим токен в `globals.css` и
  `@theme inline`, потом используем.
- **Только один источник форматирования.** Никакого дублирования
  `formatCurrency` / `formatDate` по файлам — всё из `lib/format.ts`.
- **Только `lucide-react` для иконок** в UI. SVG-инлайн допустим
  только для бренд-знаков (Google) в `components/icons/`.
- **Никаких новых `any`.** Все пропсы компонентов типизируем,
  для категорий — литералы из `CATEGORIES`.
- **Server Components по умолчанию.** Клиентскими делаем только
  компоненты с интерактивностью (форма, dropdown, фильтры с URL
  через `useRouter`, переключатель темы). Hero, таблица, тулбар
  на сервере — фильтрация через search params.
- **Без regressions фич.** После каждого этапа CRUD транзакций,
  логин, регистрация, блокировка и удаление пользователя
  работают так же, как до редизайна. Дизайн не ломает
  Server Actions, RLS, middleware и admin-клиент.
